# Result Envelope Parsing — Recon Report

Marker: AEON_OS_E2E_2026-09-10T16-37-07-347Z-4eb7a5_02

Scope: `apps/kairos-worker/src/envelope.ts` and its tests in
`apps/kairos-worker/src/envelope.test.ts`. This module recovers a mission's
terminal JSON result envelope from a raw engine transcript and canonicalizes
its `status` field before Aeon persists it.

## Findings (observed in source)

1. **Status aliasing uses a null-prototype map to block prototype-pollution
   spoofing.** `STATUS_ALIASES` is built with `Object.assign(Object.create(null), {...})`
   (`apps/kairos-worker/src/envelope.ts:16-19`), and the surrounding comment
   explains this specifically prevents a `status` value of `__proto__` or
   `constructor` from resolving to an inherited member and masquerading as a
   valid alias (`apps/kairos-worker/src/envelope.ts:14-15`). This is verified
   by a dedicated test asserting `__proto__`, `constructor`, and `toString`
   pass through untouched rather than aliasing
   (`apps/kairos-worker/src/envelope.test.ts:37-40`).

2. **`extractEnvelope` guards against the engine echoing the dispatch
   template back as its own answer.** The dispatch prompt shows engines a
   fenced JSON template with `"status":"completed|needs_input|failed"`,
   which is syntactically valid JSON but not a real verdict. `extractEnvelope`
   scans fenced ```json blocks from last to first and only returns a block
   immediately if `looksLikeEnvelope` confirms its status normalizes to a
   canonical value; the pipe character is explicitly rejected in
   `looksLikeEnvelope` (`apps/kairos-worker/src/envelope.ts:96-101`,
   `apps/kairos-worker/src/envelope.ts:103-113`). Otherwise it falls back to
   the last parseable block (`apps/kairos-worker/src/envelope.ts:105,110,112`).
   Tests confirm the template is ignored whether it appears before or after
   the real envelope (`apps/kairos-worker/src/envelope.test.ts:76-84`).

3. **`normalizeEnvelope` deep-sanitizes the whole payload via
   `sanitizeJsonbDeep` before touching `status`, specifically to strip NUL
   bytes that would otherwise break the Postgres jsonb write.** The comment
   at `apps/kairos-worker/src/envelope.ts:21-25` states a `\u0000` survives
   `JSON.parse` as a real NUL and Postgres rejects it with a non-retriable
   400, so every string is sanitized "before any caller sees it"
   (`apps/kairos-worker/src/envelope.ts:30`, imported from
   `./stream-parser.js` at `apps/kairos-worker/src/envelope.ts:6`). A test
   confirms NUL bytes are stripped from `summary`, array entries, and even
   object keys, and that lone surrogates are replaced
   (`apps/kairos-worker/src/envelope.test.ts:53-68`).

4. **`decideFinalStatus` gives `killed` and rejection precedence over the
   engine-reported status, so a process that Aeon actually killed or whose
   envelope it rejected can never read as a success on the board.** The order
   is: `killed` wins over everything, then `envelopeRejected` forces
   `failed`, and only then is `reportedStatus` consulted, accepting
   `completed` or `needs_input` as `succeeded`
   (`apps/kairos-worker/src/envelope.ts:45-47`, comment at
   `apps/kairos-worker/src/envelope.ts:38-39`). Tests cover killed-wins-over-
   completed and rejected-envelope-overrides-completed cases
   (`apps/kairos-worker/src/envelope.test.ts:141-142,153-156`).

5. **`collectText` recovers envelopes buried in escaped stream-json/JSONL
   transcripts by decoding `text`/`result`/`content` string fields out of
   each JSON line and appending the decoded text after the raw stream, so a
   last-block scan finds the decoded (unescaped) copy first.** Only lines
   starting with `{` are attempted as JSON (`apps/kairos-worker/src/envelope.ts:66-70`),
   and `textFragments` recurses up to depth 6 collecting only the named keys
   (`apps/kairos-worker/src/envelope.ts:75-90`). A comment at
   `apps/kairos-worker/src/envelope.ts:61-63` notes decoded text is appended
   after the raw stream specifically because "decoded wins because it is
   searched last-first" — an inference-supporting design note, confirmed
   behaviorally by the JSONL recovery test
   (`apps/kairos-worker/src/envelope.test.ts:180-190`), which also shows
   `extractEnvelope` alone returns `null` on the raw JSONL body before
   `collectText` is applied (`apps/kairos-worker/src/envelope.test.ts:187`).

## Inference (not directly asserted in code/comments)

- The alias set (`complete`, `done`, `success`, `succeeded` → `completed`;
  `failure`, `error` → `failed`) appears tuned to real-world engine behavior
  rather than a spec; the comment at `apps/kairos-worker/src/envelope.ts:11`
  ("'complete' for 'completed' cost the first Copilot mission its result")
  is the only historical justification given in-repo for this module's
  existence, implying the alias list grows reactively as new engines are
  onboarded rather than being fixed a priori.

# Recon: Result Envelope Parsing

Marker: AEON_OS_E2E_2026-09-11T12-17-25-014Z-1a3691_02

Scope: `apps/kairos-worker/src/envelope.ts` and its test file `apps/kairos-worker/src/envelope.test.ts`.

## Findings (observed in source)

1. **Status aliases use a null-prototype object to block prototype-pollution spoofing.** `STATUS_ALIASES` is built with `Object.assign(Object.create(null), {...})` specifically so a mission-reported status of `'__proto__'` or `'constructor'` cannot resolve to an inherited `Object.prototype` member and be misread as a canonical alias. See `apps/kairos-worker/src/envelope.ts:14` (comment) and `apps/kairos-worker/src/envelope.ts:16` (declaration). Confirmed by test `apps/kairos-worker/src/envelope.test.ts` case "does not treat inherited object members as aliases" (asserts `__proto__`, `constructor`, `toString` all pass through unchanged).

2. **Every envelope is deep-sanitized for jsonb-unsafe characters before any caller sees it.** `normalizeEnvelope` calls `sanitizeJsonbDeep(envelope)` (imported from `apps/kairos-worker/src/envelope.ts:6`, invoked at `apps/kairos-worker/src/envelope.ts:30`) before doing any status normalization. The adjacent comment explains the rationale: a `\u0000` NUL byte surviving `JSON.parse` causes Postgres to reject the jsonb write with a non-retriable 400, silently losing the mission's result. This is exercised by the test "deep-sanitises NUL bytes and lone surrogates so the jsonb write is accepted" in `apps/kairos-worker/src/envelope.test.ts`, which also confirms lone surrogates (`\uD800`) are replaced with the replacement character `\uFFFD`.

3. **`extractEnvelope` distinguishes a real envelope from the echoed instruction template by requiring the status to normalize to a canonical value, and rejects any status containing a literal `|`.** The template shown to engines uses a status field literal `"completed|needs_input|failed"`; `looksLikeEnvelope` (defined at `apps/kairos-worker/src/envelope.ts:96`) explicitly checks `status.includes('|')` and returns `false` for it, then only accepts blocks whose `normalizeEnvelope(...)?.status` is in `CANONICAL_STATUSES`. `extractEnvelope` (defined at `apps/kairos-worker/src/envelope.ts:103`) scans fenced ```json blocks captured via the regex at `apps/kairos-worker/src/envelope.ts:104`, walking them **last-to-first** (loop at `apps/kairos-worker/src/envelope.ts:106`) so the most recent real envelope wins even if the template is echoed before or after it, falling back to the last parseable block (`fallback ??= parsed`, `apps/kairos-worker/src/envelope.ts:110`) only when nothing looks like a real envelope.

4. **`collectText` recovers envelopes trapped inside stream-json/JSONL transcripts by decoding embedded text fields and appending them after the raw stream.** Defined at `apps/kairos-worker/src/envelope.ts:64`, it scans each line for a leading `{`, parses it as JSON, and extracts nested `text`/`result`/`content` string fields (via the depth-limited `textFragments` helper) so a fenced json block escaped inside a stream-json message becomes visible to `extractEnvelope`. This is exercised by the tests "recovers an envelope from a JSONL out-file body" and "recovers an envelope from a plain (non-JSONL) out-file body" in `apps/kairos-worker/src/envelope.test.ts`, which show that `extractEnvelope(rawJsonl)` alone returns `null` but `extractEnvelope(collectText(rawJsonl))` recovers the envelope — i.e. decoding is required, not optional, for JSONL-shaped transcripts.

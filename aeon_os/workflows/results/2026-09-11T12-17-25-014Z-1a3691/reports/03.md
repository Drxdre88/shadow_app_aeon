## Findings

1. **Destruction never calls `git worktree remove`; it hand-drops junctions
   then does a recursive `fs.rmSync`, refusing to delete if any link
   survives the scan.** This is the load-bearing safety invariant of the
   module: a header comment records it was empirically proven on git 2.52
   Windows that `git worktree remove` (with or without `--force`) traverses
   junctions and empties their targets, so destruction must go through
   `findLinks` + manual unlink first. Observed in
   `apps/kairos-worker/src/worktree.ts:398` (`removeWorktree`) and the
   `destroyLocked` body at
   `apps/kairos-worker/src/worktree.ts:402`-`apps/kairos-worker/src/worktree.ts:435`,
   with the invariant documented in the file's top-of-module comment at
   `apps/kairos-worker/src/worktree.ts:11`-`apps/kairos-worker/src/worktree.ts:17`.
   The regression lock for this behavior lives in
   `apps/kairos-worker/src/worktree.test.ts:1`-`apps/kairos-worker/src/worktree.test.ts:4`,
   which states the junction-survival tests exist specifically to guard the
   warden round-1 criticals.

2. **Worktree directories are namespaced per mission branch by a
   deterministic digest, and mission branches are restricted to a single
   `aeon/` prefix namespace to prevent operator branches from ever being
   checked out or pushed by teardown.** `worktreeDirFor` at
   `apps/kairos-worker/src/worktree.ts:158`-`apps/kairos-worker/src/worktree.ts:162`
   builds the directory as `join(worktreeRoot(), slugDir(entry.slug),
   \`${flat}-${digest}\`)`, where `digest` is a 6-character SHA1 slice of the
   branch name — this guards against sanitized-name collisions (e.g.
   `aeon/x` vs `aeon-x`), per the comment at
   `apps/kairos-worker/src/worktree.ts:155`-`apps/kairos-worker/src/worktree.ts:157`.
   `isMissionBranch` at
   `apps/kairos-worker/src/worktree.ts:139`-`apps/kairos-worker/src/worktree.ts:143`
   only accepts branches starting with `MISSION_BRANCH_PREFIX` (`'aeon/'`,
   defined at `apps/kairos-worker/src/worktree.ts:138`) and rejects any
   remainder containing a `..` path segment. This is exercised by the test
   at `apps/kairos-worker/src/worktree.test.ts:69`-`apps/kairos-worker/src/worktree.test.ts:78`
   (`worktreeDirFor` digest-disambiguation) and
   `apps/kairos-worker/src/worktree.test.ts:80`-`apps/kairos-worker/src/worktree.test.ts:86`
   (`isMissionBranch` namespace acceptance).

3. **Worktree admin operations on a single repo are serialized through a
   promise-chain mutex keyed on the case-folded resolved repo path, with a
   generous timebox sized to the worst-case sequential git-call count rather
   than a fixed guess.** `withRepoLock` at
   `apps/kairos-worker/src/worktree.ts:119` uses `repoLocks` (a
   `Map<string, Promise<unknown>>` declared at
   `apps/kairos-worker/src/worktree.ts:97`) keyed by `lockKey()`
   (`apps/kairos-worker/src/worktree.ts:104`-`apps/kairos-worker/src/worktree.ts:107`,
   lower-cased on `win32`). `LOCK_TIMEOUT_MS` at
   `apps/kairos-worker/src/worktree.ts:96` is derived from
   `MAX_LOCKED_GIT_CALLS` (9, at
   `apps/kairos-worker/src/worktree.ts:95`) multiplied by `GIT_TIMEOUT_MS`
   (120,000 ms, defined at `apps/kairos-worker/src/worktree.ts:59`) plus 60
   seconds of slack — the comment at
   `apps/kairos-worker/src/worktree.ts:90`-`apps/kairos-worker/src/worktree.ts:95`
   explains this must cover the longest locked body (create with a
   stale-entry retry: up to 9 sequential git calls) because rejecting a
   timed-out promise does not cancel the underlying git child process.

4. **`slugDir` defends the on-disk mission path against a registry slug
   that sanitizes down to nothing or to a leading dot/dash, falling back to
   a content-derived digest name.** At
   `apps/kairos-worker/src/worktree.ts:150`-`apps/kairos-worker/src/worktree.ts:153`,
   non-alphanumeric runs are collapsed to `-`, leading dots/dashes are
   stripped, and if no alphanumeric character remains the function returns
   `slug-<8-hex-chars>` from a SHA1 of the raw slug — per the comment at
   `apps/kairos-worker/src/worktree.ts:145`-`apps/kairos-worker/src/worktree.ts:149`,
   this exists because a slug of `'..'` or `'a/../..'` could otherwise place
   the mission tree outside `worktreeRoot()`.

# Recon: Engine model arguments (apps/kairos-worker/src/engines.ts)

Unique marker: AEON_OS_E2E_2026-09-11T12-17-25-014Z-1a3691_10

Scope: `apps/kairos-worker/src/engines.ts` and its focused test file
`apps/kairos-worker/src/engines.test.ts`. All citations below are observed
directly in these two files unless explicitly marked as inference.

## Findings

1. **Model selection is per-engine and falls back through a shared helper, not a hardcoded default.**
   Each adapter's `buildArgs` calls `modelArgs('--model'|'-m', opts.model, this.defaultModel)`
   (observed at `apps/kairos-worker/src/engines.ts:66` for claude, `apps/kairos-worker/src/engines.ts:88`
   for copilot, and `apps/kairos-worker/src/engines.ts:105` for codex, using the `-m` flag).
   The `modelArgs` helper itself (`apps/kairos-worker/src/engines.ts:36-39`) resolves
   `opts.model ?? fallback` and only emits the flag/value pair when a model is
   actually chosen — so when both the caller's `opts.model` and the adapter's
   `defaultModel` are null, no model flag is added to argv at all. This is
   exercised by the codex fallback test at `apps/kairos-worker/src/engines.test.ts:73-78`,
   which asserts `-m` is absent when `codex.defaultModel === null`.

2. **The three engines have different flags and default-model resolution strategies, and only copilot ships a non-null built-in default.**
   `claude`'s `defaultModel` reads `process.env.KAIROS_CLAUDE_DEFAULT_MODEL ?? null`
   (`apps/kairos-worker/src/engines.ts:75`) and `codex`'s reads
   `process.env.KAIROS_CODEX_DEFAULT_MODEL ?? null` (`apps/kairos-worker/src/engines.ts:109`) —
   both fall back to `null` (no forced model) if the env var is unset. `copilot`,
   by contrast, hardcodes a non-null fallback: `process.env.KAIROS_COPILOT_DEFAULT_MODEL ?? 'claude-sonnet-5'`
   (`apps/kairos-worker/src/engines.ts:92`), so a copilot dispatch with no explicit
   model and no env override always still gets `--model claude-sonnet-5` in argv
   (confirmed indirectly by the copilot test at `apps/kairos-worker/src/engines.test.ts:65-70`,
   which passes an explicit model rather than testing the no-model path).

3. **Claude accepts two additional model-adjacent argv knobs (`--effort`, `--fallback-model`) sourced from operator-controlled env vars, each independently validated by a shared allow-list regex before being placed in argv.**
   These are built via the same `modelArgs` helper at `apps/kairos-worker/src/engines.ts:70-71`,
   with values coming from `safeKnob('KAIROS_CLAUDE_EFFORT')` and
   `safeKnob('KAIROS_CLAUDE_FALLBACK_MODEL')`. `safeKnob` (`apps/kairos-worker/src/engines.ts:49-54`)
   reads the named env var and validates it against `SAFE_ARG`
   (`apps/kairos-worker/src/engines.ts:45`, pattern `^[A-Za-z0-9][A-Za-z0-9._:/@-]*$`);
   on failure it logs a warning and returns `null` rather than throwing, so the
   value is silently dropped from argv instead of aborting the dispatch. The
   inline comment at `apps/kairos-worker/src/engines.ts:44` explains the intent:
   the first character must be alphanumeric so a value like
   `--dangerously-skip-permissions` is rejected as a flag-shaped value rather
   than smuggled in as an argument. This exact adversarial case is covered by
   the test at `apps/kairos-worker/src/engines.test.ts:54-63`, which sets
   `KAIROS_CLAUDE_EFFORT` to `--dangerously-skip-permissions` and
   `KAIROS_CLAUDE_FALLBACK_MODEL` to `sonnet --verbose` (a value containing an
   embedded space) and asserts neither the flags nor the raw values appear in
   the resulting argv.

4. **Only the `claude` adapter builds its argv as a method using `this.defaultModel` (an object literal method, not an arrow function), which is load-bearing for its own default-model fallback.**
   `buildArgs` on the `claude` adapter (`apps/kairos-worker/src/engines.ts:61-73`) references
   `this.defaultModel` at `apps/kairos-worker/src/engines.ts:66`; the same pattern
   repeats for `copilot` (`apps/kairos-worker/src/engines.ts:88`) and `codex`
   (`apps/kairos-worker/src/engines.ts:105`). Because each is declared as a normal
   method (`buildArgs(prompt, opts) { ... }`) inside its own `const` object
   literal rather than as an arrow function, `this` binds to the adapter object
   itself at call time. *Inference:* if any of these methods were ever
   detached from their adapter object and invoked standalone (e.g.
   `const fn = claude.buildArgs; fn(...)`), `this.defaultModel` would no longer
   resolve correctly — this failure mode is not exercised by any test in
   `apps/kairos-worker/src/engines.test.ts`, all of which call
   `getEngine(id)?.buildArgs(...)` through the object reference (see
   `apps/kairos-worker/src/engines.test.ts:6`), so the binding is never
   actually stressed by the current suite.

5. **Codex is the only engine whose model flag placement is entangled with an unrelated file-output flag (`-o`), both gated by `BuildArgsOptions.outFile`/`opts.model`.**
   The codex `buildArgs` (`apps/kairos-worker/src/engines.ts:99-107`) conditionally
   spreads `['-o', opts.outFile]` at `apps/kairos-worker/src/engines.ts:102` and
   the model flag `...modelArgs('-m', opts.model, this.defaultModel)` at
   `apps/kairos-worker/src/engines.ts:105`, with `envelopeSource: 'file'` declared
   right after at `apps/kairos-worker/src/engines.ts:108` — the only adapter of
   the three not using `envelopeSource: 'stdout'` (`apps/kairos-worker/src/engines.ts:74`
   for claude, `apps/kairos-worker/src/engines.ts:91` for copilot). The test at
   `apps/kairos-worker/src/engines.test.ts:80-87` confirms `-o`, `-s`, `-C`, and
   `-m` are all populated together for codex, and the fallback test at
   `apps/kairos-worker/src/engines.test.ts:73-78` confirms `-o` is omitted
   independently of `-m` when `outFile` is `null`, showing the two flags are
   gated by separate options (`opts.outFile` vs. `opts.model`/`defaultModel`)
   even though both are conditionally spread in the same `buildArgs` call.

## Observed vs. inference

Findings 1–3 and 5 are direct observations of the source and its test
assertions. Finding 4's core claim (adapters are object-literal methods using
`this.defaultModel`) is observed; its consequence about detached-method
invocation failure is explicitly marked as inference and is not covered by
the existing test suite.

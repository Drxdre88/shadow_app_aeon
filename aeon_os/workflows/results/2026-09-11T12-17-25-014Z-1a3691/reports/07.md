# Runner Repository Registry — Recon Report

Marker: AEON_OS_E2E_2026-09-11T12-17-25-014Z-1a3691_07

Scope: `apps/kairos-worker/src/registry.ts` (host-local repo registry for poll
mode) and its test file `apps/kairos-worker/src/registry.test.ts`. All
findings below are observed directly in these two files unless explicitly
marked as inference.

## Findings

1. **Slug validation blocks path traversal and prototype-pollution slugs, not
   just "nice" names.** The registry key is used both as an object property
   and a filesystem path component, so it is constrained by
   `SAFE_SLUG = /^[A-Za-z0-9][A-Za-z0-9._-]*$/` (apps/kairos-worker/src/registry.ts:39)
   enforced through `safeSlug()` (apps/kairos-worker/src/registry.ts:41-43).
   Rejected slugs are logged and dropped inside `loadRepos()`'s parse loop
   (apps/kairos-worker/src/registry.ts:119-124). This is confirmed by the test
   `'drops a registry key that is not a plain path component'`
   (apps/kairos-worker/src/registry.test.ts:193-207), which asserts that keys
   `'..'`, `'.hidden'`, `'-flag'`, and `'__proto__'` are all excluded from
   `loadRepos()` output while a normal key (`good`) survives.

2. **`resolveRepo()` uses `Object.hasOwn` rather than a bare index lookup to
   stop prototype-chain slugs (e.g. `constructor`, `toString`) from resolving
   to an inherited value as if it were a real `RepoEntry`**
   (apps/kairos-worker/src/registry.ts:138-144, with the guarding comment at
   apps/kairos-worker/src/registry.ts:139-141). This is a second, independent
   layer of defense beyond the `SAFE_SLUG` filter in finding 1: even if a
   disallowed key somehow existed in the parsed `repos` map, `resolveRepo`
   would still refuse to hand it back for names like `'__proto__'`,
   `'constructor'`, `'toString'`, `'hasOwnProperty'`, `'valueOf'`. Test
   coverage: `'never resolves a slug through the prototype chain'`
   (apps/kairos-worker/src/registry.test.ts:178-191).

3. **The hand-rolled YAML parser's comment-stripping is deliberately narrow so
   it does not corrupt Windows paths or URLs containing a literal `#`.**
   `stripComment()` only treats a `#` as a comment opener when it is either at
   the very start of the line or preceded by whitespace (via
   `/\s#/.exec(line)`), implemented at apps/kairos-worker/src/registry.ts:59-63.
   This is verified by the test `'strips trailing comments without eating a
   hash inside a path'` (apps/kairos-worker/src/registry.test.ts:53-66), which
   feeds the parser a path `C:/x#y` followed by a real trailing comment and
   asserts the parsed path keeps the `#y` suffix intact while the comment is
   removed.

4. **Repos with a missing/blank `path` are silently excluded from the loaded
   registry rather than surfaced as an error**, per the `if (!path) continue`
   guard in the `loadRepos()` entry-building loop
   (apps/kairos-worker/src/registry.ts:119-120). This is exercised by the test
   `'skips entries with no path — an unusable repo must not be claimable'`
   (apps/kairos-worker/src/registry.test.ts:105-120), which shows an entry with
   no `path` key and an entry with `path: ~` (parsed to `null` by `scalar()`,
   apps/kairos-worker/src/registry.ts:65-69) are both dropped, leaving only the
   valid `real` entry.

5. **`getWorkerId()` persists a random 3-byte hex suffix alongside the repos
   file (in a sibling `.worker-id` file) so the worker's identity is stable
   across restarts, combining it with `os.hostname()`**
   (apps/kairos-worker/src/registry.ts:147-160). Inference: because the file
   path is derived from `dirname(reposFilePath())`
   (apps/kairos-worker/src/registry.ts:148), this file lives next to whatever
   `KAIROS_REPOS_FILE` currently points at, meaning tests that redirect
   `KAIROS_REPOS_FILE` to a temp directory (e.g.
   apps/kairos-worker/src/registry.test.ts:15-22) would also relocate where a
   `.worker-id` file gets written if `getWorkerId()` were called under test —
   though no test in `registry.test.ts` actually exercises `getWorkerId()`
   (observed: it is not referenced anywhere in
   apps/kairos-worker/src/registry.test.ts).

## Observed vs. inferred

- Findings 1–4 are directly observed from source and confirmed by an existing
  test in the same file.
- Finding 5's core mechanics (hostname + persisted random suffix) are
  observed directly; the claim about `.worker-id` following a redirected
  `KAIROS_REPOS_FILE` in tests is inference from reading the code path, since
  no test in `registry.test.ts` calls `getWorkerId()` to confirm it.

## A. Four live production defects

### A1. Evening digest 27/09 delivered a WordPress manual
- **Cause (confirmed):** `lib/kairos/digest.ts:241-250` calls `provider.ask({ system, prompt, cacheSystem:true, maxTokens:1500 })`, reads only `.text`, checks only `!text`, then forwards raw model text to `deliverKairosSpeak` (`:268`) which bypasses `speakSchema` (internal caller) → stored as inbox memory `f56b2664` and chunked to Telegram (`telegram.ts:252-289`, split at 3500 chars). `renderTelegramHtml` turned the junk markdown link into a live `<a href>`.
- **Trigger (inferred, strong):** model never emitted end_turn; free-ran into memorised pretraining text ("Powered by Claude Exporter" export footer → wp-config manual) until the 1500-token cap. Body ends mid-word "Before we go de" = `finishReason:'length'`. No context-injection path exists: `toSdkArgs` (`lib/ai/provider.ts:133-143`) sends exactly two messages (static system + counts). Provider IS returning `finishReason` (`provider.ts:171`); digest drops it.
- **Fix:** inside the existing try after `digest.ts:248`:
  ```ts
  if (response.finishReason !== 'stop') throw new Error(`digest: finishReason=${response.finishReason}`)
  if (text.length > 1200 || /^#{1,6}\s|https?:\/\/|Powered by/im.test(text)) throw new Error('digest: output rejected by guard')
  ```
  The catch (`:251-262`) already falls back to `buildDeterministicDigest` and writes `model_call_failed`; add `finishReason` + `rawExcerpt: text.slice(0,500)` to that trace (fields exist on `CronFailureTraceInput`, `cron-trace.ts:29-32`). Tests: `digest.test.ts:254/387/408` mock `finishReason:'stop'` → still pass.
- **Same defect class:** Telegram chat reply path (`app/api/telegram/webhook/route.ts:184-198`, `chat-turn.ts:230-243` ignores finishReason, no length guard). Speak route (`api/v1/kairos/speak/route.ts:43-48`) only enforces 20k max. Optional defence: cap `message` length inside `deliverKairosSpeak`.

### A2. aether-regen 28/09 `parse_failed` (Invalid UUID thoughts[4..14].id, tensions aId/bId)
- **Cause (confirmed):** `aether-prompt.ts:141,147` tells the model to mint UUID v4s; schema `aether-prompt.ts:9,17,22-23` uses `z.string().uuid()`; zod 4.4.3 is strict RFC 9562 (version nibble 1-8, variant 8/9/a/b). Model-invented ids drift; copied ids (sourceMemoryIds, dominionId) passed. Tensions fail because they reference the invented ids → one defect.
- **Why repair failed:** aether does NOT use the shared `parseWithRepair` (`_prompt-utils.ts:119-141`); it has an older private copy `aether.ts:348-367 / 386-398` that sends no system prompt and no valid-id list. Failure trace (`aether.ts:364`) carries no `finishReason`/`rawExcerpt`.
- **Fix:** (1) `aetherGenSchema` = `aetherOutSchema` with `id/aId/bId` as `z.string().trim().min(1).max(64)`; keep `aetherOutSchema` as the STORED contract. (2) Prompt: "`id`: a short label unique within this response (e.g. t1)". (3) In `parseAndGround` (`aether.ts:338-346`): filter ungrounded, then mint `randomUUID()` per thought, remap tensions via a Map, drop tensions whose ends are missing or equal (also fixes today's dangling-tension latent bug). (4) Switch repair to `parseWithRepair({ system: AETHER_SYSTEM_PROMPT, repairContext: <valid memory ids> })`, pass finishReason/rawExcerpt to the trace.
- **Consumer safety (confirmed):** stored payload keeps real UUIDs → `ask-select.ts:96,104-105`, `ask-mine.ts:158,168-170`, `dialogue.ts:136`, `lib/data/ask.ts:298`, `lib/data/aether.ts:25`, `renderAetherMarkdown` (`aether-prompt.ts:269`) unchanged. No component reads thought ids. MCP `commit_aether` (`app/api/[transport]/tools/synthesis.ts:50`) uses `aetherOutSchema`; leave or add mint.
- **Tests:** `lib/kairos/__tests__/aether.test.ts:109-191`, `aether-prompt.test.ts:198`.
- **Note:** cortex-regen failed the same way 17/09 (`activeThreads[3].id` null → repair produced invalid UUID). Same fix pattern applies to cortex ids.

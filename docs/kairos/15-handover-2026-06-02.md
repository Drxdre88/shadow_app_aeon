## Open design questions for C2 (memory-grounded responses)

These are the calls the next session needs to make. None blocking — defaults below are my picks unless the owner overrides.

### 1. Citation format
**Options:**
- Inline `[[memory-id]]` markers in the assistant body — model decides where to cite
- Footnote-style `[^1]` numbered markers with a sources list at the end
- Sidebar panel showing which memories were considered (no inline markup)

**Recommendation:** Inline `[[uuid]]` markers, post-processed by the UI to render as small chips that hover-expand to show the memory title + snippet. Matches `prepareContext`'s existing `[ID]` convention and is what the evolution plan calls for.

### 2. Retrieval scope per turn
**Options:**
- Always include cortex + top-k FTS from the Dominion's substrate
- Include cortex always; add FTS retrieval only when the user message looks like a "question about specifics"
- Let the model decide via a tool call (Phase 2+)

**Recommendation:** Cortex always (it's small, already synthesised), plus top-5 FTS hits over the Dominion's last 90 days of substrate. Cheap, predictable, no tool-calling complexity.

### 3. Top-k tuning
- Cortex: always 1 row (the live cortex for the anchored Dominion)
- Archetypes: always include all today's archetypes (≤7)
- Substrate: top-5 by FTS rank over `streamClass IN ('reflection', 'idea', 'agentic')`, last 90 days

### 4. UI affordance for "thinking about..."
Should the Visor show *what* it retrieved before generating? Options:
- Silent (matches current chat UX)
- Inline "Reading: 3 archetypes, 2 reflections, 4 memories" line just above the assistant reply
- Expandable "Sources" panel that opens on demand

**Recommendation:** Inline "Reading: ..." line, dim/small, above the assistant bubble. Honest about what's grounding the answer; doesn't bury sources.

### 5. Budget cap
Single-turn context budget: how many tokens of retrieved substrate?
- Cortex body ≈ 500 tokens
- 5 substrate memories ≈ 2,500 tokens
- All today's archetypes ≈ 1,500 tokens
- Chat history (last 30) variable, cap at ~5,000

**Recommendation:** ~10k budget total for retrieved + history, fits comfortably in standard-tier models. Trim oldest history first if over.

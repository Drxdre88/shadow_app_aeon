## Five goals — honest state at session close

### 1. Knowledge base
**State:** ~60%. Schema, FTS, taxonomy (14 memory types), tags, edges, REST + MCP all live. Three ingestion paths: manual capture, board/project event capture, session-end hook. Volume is healthy (~1000+ memories).
**Gap:** **memory quality filter is missing.** Anything that gets POSTed lands. No length floor, no semantic-noise rejection, no dedup beyond externalId. This session demonstrated the failure mode at scale.

### 2. Self-evolving hooks / automation
**State:** ~50%. What runs today:
- `claude-session-capture.mjs` SessionEnd hook → posts session_summary memories per Claude session
- `captureBoardEvent` from board mutations → snapshot memory per task action
- `captureProjectEvent` from project mutations → snapshot per project change
- Nightly `/api/cron/project-snapshot` → per-active-project state snapshot
- Nightly `/api/cron/briefer` → one advisory per active Dominion

**Gap:** No **aging / pruning** — old snapshots accumulate forever. No **memory compaction** (consolidating N session_summaries into one weekly digest). No **quality gate** (low-signal noise still lands). No **backwards links** from action → existing memory (every event creates new instead of updating).

### 3. Regular summaries aligned with vision
**State:** ~40%. Briefer runs daily, BYOK-gated, idempotent. It reads recent project snapshots + advisory state.
**Gap:** Briefer doesn't actually **reflect against `dominion.vision` / `dominion.missionLong`**. It generates advisories from recent activity but the strategic anchor is absent. Should at minimum compare "what happened this week" vs "what the Dominion is for" and flag drift.

### 4. Self-evolving task manager (self-generated questions)
**State:** ~0%. This is the biggest net-new piece. Kairos currently READS the board state but never WRITES BACK. It cannot:
- Promote an idea memory to a board card
- Ask the operator "should this become a task?"
- Detect stalled work and surface it as a question
- Generate weekly planning prompts from memory patterns

**Path:** This sits on top of #5 (chat). With chat, "Kairos asks a question" becomes a UX primitive; without it, it's just another notification.

### 5. Chat interface linked to memory cortex
**State:** ~10%. Live Sessions exists (CLI agent spawn + transcript polling) but that's an external-agent surface, not a Kairos voice. Hyperspace Notes Bento has a capture fab but no conversation.
**Gap:** No **persistent Kairos chat thread** that grounds every reply in retrieved memories. No way to say "Kairos, what did I decide about X" and get a memory-anchored answer with cite-back links. This is the missing primary surface.

## Strategic verdict

**Bulk-importing board tasks was the wrong move.** Tasks already live in `boardTasks` — the Briefer / Kairos can query them directly. Bulk memory import dilutes the cortex with low-signal noise. Two corrective actions:

1. **Prune** the empty-shell board task memories (keep rich ones + all 24 rollups). Quick SQL or a script that filters by body length / description presence.
2. **Stop relying on bulk import** for task ingestion going forward. The auto-capture path (`captureBoardEvent` on mutations) already exists; let mutations be the only source.

**The actual unlock for the Kairos brain is goal #5 — chat.** Once chat exists, #4 follows, #3 quality lifts (chat can ask Kairos to refresh a digest), and the cortex transitions from write-only log to two-way thinking partner.

**Out of scope for Phase 1:** voice loop, ambient pill animation, multi-agent coordination, self-evolving questions (Phase 2).
